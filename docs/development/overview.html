QuadStock implementation reference

This searchable Java reference documents the Paper plugin's implementation contracts. It is not a public HTTP API or a supported third-party Java SDK.

Architecture

QuadStockPlugin delegates lifecycle to MarketRuntime. Commands use MarketCommands. Ticker-scoped models and trading desks share one calendar, SQLite database and economy gateway. MarketMenus owns inventory lifecycle; focused screen classes render trading, charts, portfolios and reports.

Critical contracts

Application mutations and Vault calls run on the Paper server thread. QuickShop callbacks queue scalar observations. Market time is independent of daylight. Only committed journal operations change holdings. Uncertain payments are reconciled without repeating provider calls.

Persistence

SQLite stores normalized payment intents/transitions and named application checkpoints. A failed journal write blocks further settlement. Startup replays the journal once; a payment transition appends rows rather than rewriting all history. Database transactions cannot make an external economy-provider call atomic.
